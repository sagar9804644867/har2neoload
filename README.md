# ⚡ HAR2NeoLoad

Turn a browser **HAR** or Fiddler **SAZ** recording into a ready-to-run **NeoLoad** project - with noise removed,
dynamic values **auto-correlated** and user input **auto-parameterized**.

Built with Streamlit. Output follows the official NeoLoad **as-code v3** schema
([neoload-models](https://github.com/Neotys-Labs/neoload-models)), and every generated file is validated against it in the test suite.

## What it does

| Step | What happens |
|---|---|
| 1. Hosts | Lists every host in the recording and unticks browser telemetry, analytics, ads and OS-update traffic (Edge OneCollector, Bing, Google Analytics, etc.). Static files and CORS preflights can be excluded. |
| 2. Transactions | Groups requests into business transactions (per HAR page, per HTML document, or after a user pause). Rename them and place them in Init / Actions / End. Recorded think times are kept. |
| 3. Auto-correlation | For every value the client sends (query, form, JSON, `Authorization`, custom headers, IDs in URL paths) it searches earlier responses. Server-generated values become NeoLoad **variable extractors**: JSONPath for JSON responses, regex for HTML, header regex for `Location`/`Set-Cookie`, and form-field extractors for hidden `<input>`s (CSRF tokens, ViewState, hidden prices/IDs). The hard-coded value is replaced with `${variable}` in every later request. |
| 4. Auto-parameterization | Detects user input (login, email, password, search, cities, dates, names, card, amounts…) and moves it into NeoLoad **File variables**: `credentials` (unique per VU) and `testdata` (new row each iteration). Add rows directly in the app. |
| 5. Export | A zip with `default.yaml`, `data/*.csv`, a Postman collection (with extractor scripts), and a correlation report. |

Values that look dynamic but never appear in an earlier response (usually generated by JavaScript) are flagged under **Needs manual review**.

## Output

```
<Project>/
├── neoload_project/
│   ├── default.yaml          # NeoLoad as-code: variables, servers, user path, populations, scenarios
│   ├── data/credentials.csv
│   ├── data/testdata.csv
│   └── HOW_TO_USE.md
├── postman/
│   ├── collection.json       # alternative import route (NeoLoad "Postman import")
│   └── data.csv
└── correlation_report.md
```

Scenarios included: `Smoke_1VU` (1 user, 1 iteration - validate first) and `Load_Test` (constant load with ramp-up).

## Using the project in NeoLoad

The NeoLoad GUI cannot open YAML directly, so the zip contains two forms of the script:

- **NeoLoad GUI:** *User Paths > New User Path > Postman import* with `postman/collection.json`, then add the extractors listed in `correlation_report.md`.
- **NeoLoadCmd:** copy `default.yaml` and `data/` next to your `.nlp`, then run
  `NeoLoadCmd -project "MyProject.nlp" "default.yaml" -launch Smoke_1VU -noGUI`.
- **NeoLoad Web:** zip `neoload_project/` and upload it in *Run a test*; `default.yaml` loads automatically.

Always run the smoke scenario / **Check User Path** and compare with the recording before a load test.

## Run locally

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Toggle **Use sample recording** to try it without your own HAR.

## Deploy on Streamlit Community Cloud

1. Create a new GitHub repository (e.g. `har2neoload`) and push this folder:
   ```bash
   git init && git add . && git commit -m "HAR2NeoLoad"
   git branch -M main
   git remote add origin https://github.com/<your-user>/har2neoload.git
   git push -u origin main
   ```
2. Go to [share.streamlit.io](https://share.streamlit.io) → **Create app** → pick the repo, branch `main`, main file `app.py`.
3. Deploy. Python dependencies come from `requirements.txt`.

## Capturing a good recording

- **Chrome / Edge:** F12 → Network → tick *Preserve log* and *Disable cache* → run the flow → right-click → *Save all as HAR with content*.
- **Fiddler:** File → Save → All Sessions → `.saz`.
- Prefer Chrome or Firefox over Edge (less background traffic). Record one clean business flow per file.
- HAR files contain cookies and passwords - use test accounts.

## Tests

```bash
pip install pytest jsonschema
python -m pytest -q
```

The tests build the sample HAR and SAZ, check correlation and parameterization, and validate the generated YAML against `schema/as-code.schema.json`.

## Limitations

- Values created by client-side JavaScript (hashes, timestamps, signatures) can't be found in responses; they are flagged for manual work (NeoLoad JavaScript action).
- WebSocket, gRPC and binary/multipart bodies are not converted.
- Transactions can be renamed and moved between containers, not merged or split.
